# Dedicated Excel bridge protocol 1.0

This is a **source-only, unverified integration boundary**. Import `PrivateEngineBridge.bas` into a newly created, separately reviewed `.xlsm` or `.xlsb` workbook dedicated to one broker session. No workbook is created, opened, or connected by this repository. Never import the module into a workbook that is already open for unrelated work. Do not enable macros, alter Trust Center settings, auto-login, or add worksheet order formulas as part of this framework.

Define workbook-scoped named ranges in that dedicated workbook: `BridgeProtocolVersion` (`1.0`), `BridgeGeneration` (unique local session generation), `BridgeRequestID`, `BridgeBroker`, `BridgeCommand`, `BridgeArgCount`, `BridgeArgs` (19 rows × 1 column), `BridgeResponseRequestID`, `BridgeResponseStatus`, and `BridgeResponseValue`. The VBA module uses `ThisWorkbook.Names`, so an active workbook cannot redirect these cells. Only `PrivateEngineBridge.BridgeExecute` is callable by the Python bridge. The allowlist contains `RssStockOrder_V`, `RssCancelOrder_V`, `SntExecEqtyOrder`, and `SntExecCancelOrder`; all are cash-equity functions. The module records `UNKNOWN` even when a VBA function returns, because that return is not proof of broker acceptance or execution.

`ExcelBridge` runs its injected workbook factory on one Windows STA worker and serializes all calls. The factory must open **exactly** the configured absolute workbook path, report it through `full_name`, and implement `read_named`, `write_named`, `run_macro`, and `close`; it must not attach to an arbitrary existing Excel instance. Tests use a mock factory only. A separate durable, atomic `reserve_request(broker, generation, request_id, payload_hash)` callback is required. `True` means newly reserved; `False` means an identical ID was already reserved, so the bridge returns `UNKNOWN` without calling VBA. A different payload for an ID must raise. Rakuten request IDs are only unique within the Excel generation and may reset after Excel closes. NeoTrade order-management IDs must never be reused across generations; the durable guard must enforce this. Any `UNKNOWN` result poisons that bridge session for *new* commands until independent reconciliation; replaying the same command only returns the saved `UNKNOWN` and never calls VBA. The bridge refuses a generation mismatch, COM timeout, busy/disconnected workbook, mismatched response ID, and incomplete result; it never retries ambiguous submission. If `close()` reports a still-running STA worker, do not kill an unknown Excel process.

The official source contracts are [Rakuten cash-stock VBA order and cancel](https://marketspeed.jp/ms2_rss/onlinehelp/ohm_002/ohm_002_06.html) and [SBI NeoTrade VBA function PDF](https://www.sbineotrade.jp/manual/pdf/manual_api_VBA_function.pdf). The Rakuten mapper supplies all 19 `RssStockOrder_V` positions, using regular order/SOR off/DAY and leaving stop and linked-order positions unused. The NeoTrade mapper supplies V01's first 11 mandatory positions; position 9 is expiry type `1` (DAY), position 10 is `""`, and position 11 is general/specified account. Cancel functions take **broker order IDs**, not request IDs. No credit, NISA, stop, linked, or after-hours orders are mapped.

Query functions are identified in [Rakuten order/execution help](https://marketspeed.jp/ms2_rss/onlinehelp/ohm_002/ohm_002_05.html) and the NeoTrade PDF, but Excel list outputs, paging, callback timing, and completion evidence have not been validated through COM. Therefore Excel query/reconciliation and account import are **unavailable** in this release. A caller must not clear an `UNKNOWN` store state using a VBA call result. Kabu query mapping is mock-tested separately. No desktop COM, terminal, broker account, or live order was used or validated.
